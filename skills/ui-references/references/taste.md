# Build the reference in our product

Adapted from Mobbin's MIT-licensed taste and preservation guidance. See [upstream notices](../UPSTREAM.md).

Use the project's design system, then the chosen reference's structural decisions, then the following judgement rules. A reference demonstrates an arrangement; it does not authorize replacing the product's identity.

- Add a control, icon, badge, panel, divider, shadow or line of copy only when it solves a named problem. Open space needs no decoration.
- Give new elements the same components and treatments as existing elements doing the same job. Use the established type, spacing and colour roles.
- Make the next step apparent. Keep supporting information subordinate and beside the decision it supports.
- Align to existing edges. Keep related content closer together than unrelated groups; avoid nesting panels without a separate grouping need.
- Preserve domain content, working controls and safety information. A quieter screen still exposes what a person needs to act correctly.
- Keep platform conventions for navigation, dismissing, focus and primary actions. Borrow mobile interaction patterns for mobile surfaces, not indiscriminately for desktop.
- Use existing accent and surface roles sparingly. A foreign gradient or a newly invented palette is a theme change, not ordinary polish.
- Compare the changed element to its nearest unchanged peer. It should belong to the same product.

For this user's references, smooth and minimal are useful selection preferences, not a template every project must adopt. Herdr is a user-liked example; T3 Code and other catalogue products are optional candidates. The catalogue names places to inspect, not an automatic style authority. The target product and current brief decide.

## Finance and crypto

Keep amounts, units, fiat/asset distinctions, fees, exchange rates, networks, destinations, pending/failed states and confirmation information visible where required. Do not simplify by dropping precision, masking risk information, changing transaction meaning or inventing account data. Signing, transferring, trading and irreversible actions stay outside reference collection.

## Smoothness

Use existing motion and interaction patterns. Measure or exercise responsiveness rather than inferring it from a screenshot. Check keyboard focus, scroll behaviour, interruptibility and reduced-motion behaviour. A flourish is optional; immediate, legible feedback and stable layout matter more. Never add motion solely to satisfy a signature-interaction requirement.
